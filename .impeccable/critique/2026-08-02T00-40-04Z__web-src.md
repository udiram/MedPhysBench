## Anti-pattern verdict

The interface does not read as generic AI-generated SaaS UI. It uses a consistent scientific-instrument register, a restrained accent, square geometry, directly labeled statistical marks, and real benchmark artifacts. The deterministic detector returned zero findings across `web/src`.

The main pre-change AI-like pattern was structural: a long sequence of equal-weight evidence panels made the page feel assembled rather than argued. The new release decision header, evidence gates, capability matrix, and disjoint failure analysis establish a clearer reading path.

## Overall impression

The strongest design decision is now the first one the reader sees: what the selected release can and cannot support. The largest residual product risk is that all public lanes remain development or provisional evidence, while the visual polish can make them feel more mature than the review and holdout state actually permits.

## What's working

- Exact comparison groups and native audits are visibly separate.
- Capability and failure views use descriptive task-type groups and mutually exclusive outcomes instead of decorative aggregate charts; independent family counts remain separate.
- Mobile has a semantic interval-list fallback, visible keyboard focus, strong contrast, and horizontally scrollable dense evidence tables.

## Priority issues

### P0 — Evidence maturity remains below the visual maturity

The public benchmark has no operating protected holdout, completed human baseline, or completed independent review for the OpenKBP pilot. Keep provisional/development labels visible and prioritize those programs before stronger leaderboard claims.

Suggested command: `$impeccable harden`

### P1 — Initial data is still client-loaded

The first server render knows the release identity but not the scored rows. Loading states no longer make false empty-result claims, but server-provided summary data or an inline signed summary would improve first paint, crawlers, and slow-network trust.

Suggested command: `$impeccable optimize`

### P1 — Legacy projections expose less attempt-level evidence

The core and TG-263 projections do not expose the same per-attempt pass labels as the OpenKBP projection. The UI now refuses to impute failure partitions and falls back to domain aggregates, but a versioned reporting projection should normalize this contract.

Suggested command: `$impeccable harden`

### P2 — Lower-page provenance remains dense

The documentation wall was reduced to eight primary links, but the results, efficiency, coverage, methods, governance, and integrity sections still create a long page. A future route-based report with Overview, Capabilities, Efficiency, and Provenance tabs would reduce vertical scanning.

Suggested command: `$impeccable distill`

## Persona red flags

**Medical-physics researcher:** Can now see family counts, attempts, review state, and release limits before scores. The remaining red flag is that no human baseline or independent review is complete for the most clinically recognizable lane.

**Model-evaluation engineer:** Can audit exact comparison groups, uncertainty, telemetry, hashes, and JSON. The remaining friction is the inconsistent legacy attempt-level projection contract.

**Mobile reader:** Gets a readable decision header, focusable controls, and interval list. Dense tables require intentional horizontal scrolling; this is acceptable for audit detail but should not become the only mobile view.

## Minor observations
